# # Revenue Analysis by Film Category | PostgreSQL

## Overview

This project was completed as part of **Advanced Data Management (D326)** at Western Governors University.

The objective was to design and implement a database reporting solution that analyzes revenue generated by film categories in a DVD rental database. The solution includes custom functions, detailed and summary reporting tables, triggers, and automated procedures to support business decision-making and reporting.

The project demonstrates advanced SQL development, database automation, ETL concepts, and PostgreSQL programming techniques.

---

## Business Problem

A movie rental company wants to understand:

> Which film categories generate the most revenue?

By identifying high-performing and low-performing film categories, management can make informed decisions regarding:

- Marketing investments
- Inventory management
- Revenue optimization
- Strategic planning
- Category expansion or reduction

## Project Components

### Detailed Revenue Table

The detailed reporting table captures transaction-level information including:

- Customer ID
- Customer Name
- Film ID
- Film Category
- Rental Date
- Payment Amount

This table provides granular data for analysis and auditing.

### Summary Revenue Table

The summary table aggregates revenue by category and answers the business question directly.

Metrics include:

- Category Name
- Total Revenue

---

## Database Objects Created

### Custom Function

A reusable PostgreSQL function was created to combine customer first and last names into a formatted field.

```sql
format_customer_name(
    p_first_name TEXT,
    p_last_name TEXT
)
```

Purpose:

- Improve report readability
- Eliminate repetitive formatting logic
- Promote code reuse

---

### Reporting Tables

#### Detailed Table

```sql
detailed_revenue_by_category
```

Stores individual rental transactions for reporting.

#### Summary Table

```sql
summary_revenue_by_category
```

Stores aggregated revenue totals by film category.

---

### Trigger Function

A trigger function was implemented to automatically update category revenue totals whenever new transaction data is inserted into the detailed table.

Benefits:

- Automated aggregation
- Improved reporting accuracy
- Reduced manual maintenance

---

### Database Trigger

```sql
trg_after_insert_update_summary
```

Automatically executes after inserts occur in the detailed table.

Responsibilities:

- Update revenue totals
- Keep summary data synchronized
- Support real-time reporting

---

### Stored Procedure

```sql
refresh_revenue_report()
```

The procedure refreshes the reporting solution by:

1. Clearing existing report data
2. Reloading detailed transaction data
3. Rebuilding summary calculations
4. Preparing the report for analysis

This supports scheduled report generation and automation.
